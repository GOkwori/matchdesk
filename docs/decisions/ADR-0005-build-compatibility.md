# ADR-0005: Resolve dependency incompatibilities without relaxing checks

Date: 8 October 2026. Status: selected for hosted qualification; not a production certification.

## Context

The first locked build [37750545499](https://github.com/GOkwori/matchdesk/actions/runs/37750545499)
used source `56b708990dd748649da5cc44f9f099f78a940aaf`, Python 3.12.15 and Node 22.16.0.
Package installation and repository checks passed. Strict mypy passed for seven source
files. Pytest failed during collection, before running assertions: Starlette 0.50.0
references `anyio.abc.BlockingPortal`, deprecated in the resolved AnyIO 4.15.1.
The existing warning-as-error policy correctly made that incompatibility visible.

TypeScript 5.8.3 could not resolve `URLPatternInput`, `URLPatternOptions` and `URLPattern`
in Next.js 16.4.0's declaration files. The frontend compiled its JavaScript but failed
its type-checking stage; that is a failed build, not a working deployment.
Ruff also reported import ordering and formatting differences.

## Decision

I am retaining the strict checks and correcting the dependency boundary instead of
hiding the failures. The Python resolver constrains AnyIO to 4.13.0 for the existing
FastAPI/Starlette pair. This is a narrow compatibility constraint, not a permanent
rejection of newer AnyIO. Remove it only with a qualified framework upgrade and the
same warning-as-error tests. The local foundation had already executed with 4.13.0;
the hosted Python 3.12 suite must independently confirm the combination.

The frontend uses TypeScript 6.0.3, with explicit Node/React ambient type selection.
Next.js's documented JSX runtime configuration and generated-type include paths are
recorded intentionally. `strict: true` and `skipLibCheck: false` remain unchanged.
A compile-only platform-types regression checks that URLPattern declarations remain
known types and still reject invalid input. No ambient any declaration is introduced.

Ruff's generated patch is reviewed separately from dependency changes. The
[formatting review](../evidence/formatting-review-20261008.json) records the expected
file hashes after checking unchanged functional AST, import bindings, docstrings and
comments. A hosted formatter must reproduce those bytes before they are imported.

## Alternatives and consequences

Suppressing the warning or enabling skipLibCheck would hide rather than resolve the
problem. Upgrading the whole Python framework stack would increase the change scope.
The selected pins require renewed dependency security auditing; neither a successful
resolver nor a passing test suite is a blanket security assurance. Lockfiles must be
regenerated by the actual resolvers and the independent CI run must pass on the
committed source. The intermediate stale-lock failure is expected until candidates
are reviewed and imported; no check is bypassed.
