# Verifier benchmark and speed, 24 October 2026

## Try to fool the verifier

`matchdesk.domain.verifier_benchmark` takes each of the 79 verified claims the overlays,
recaps and stories show and makes it wrong in one way at a time, the way a fluent model gets
a sentence wrong. It also rewords the true claims in ways a reader would accept. The cases
are generated deterministically (no randomness, no hand-picking), regenerated by
`scripts/export_demo_data.py` and checked on every build: `backend/tests/test_verifier_benchmark.py`
runs the server verifier, and `apps/web/tests/verifier.benchmark.test.mjs` runs the browser
port on the same 1,105 cases and requires the same verdict and query on each.

| Kind of error | Caught |
| --- | --- |
| A wrong number, stated consistently in the sentence and its assertion | 190 / 190 |
| The sentence states a different number from the one it asserts | 190 / 190 |
| The sentence names the wrong player or team | 64 / 64 |
| The claim is about a different player than the sentence names | 15 / 15 |
| The sentence states the wrong half, minute range or time | 64 / 64 |
| The sentence names a different statistic | 64 / 64 |
| The claim cites events that do not support it, or do not exist | 114 / 114 |
| The claim speaks about time the evidence does not cover | 64 / 64 |
| A goal credited to the wrong player | 18 / 18 |
| A card with the wrong colour, or the wrong player booked | 4 / 4 |
| A substitution with the players swapped or wrong | 2 / 2 |
| A goal's build-up timed wrongly | 9 / 9 |
| An event placed at the wrong time | 12 / 12 |
| **All false claims** | **810 / 810** |

| True claims | Verified |
| --- | --- |
| The claim as the demo shows it | 79 / 79 |
| Reworded with the time phrase first | 64 / 64 |
| Reworded with "a total of" | 40 / 40 |
| Number words and synonyms ("five", "of the ball", "by 58:18", "took", "netted") | 112 / 112 |
| **All true claims** | **295 / 295** (none wrongly rejected) |

**What it found.** While the benchmark was being built, one case got through: a substitution
written the wrong way round ("Barros replaced Kovac" when Kovac replaced Barros) verified,
because the check only required the incoming player to be named. The verifier now also checks
the order ("A replaced B", "A came on for B" against "B was replaced by A", "B off for A"), on
the server (`claim_text.py`) and in the browser (`verifier.ts`), with two new parity cases.

**What it does not show.** The cases test the verifier's own rules, written by the same team,
so a full score shows the rules work as designed, not that no other kind of error exists. Out
of scope by design: tone and judgement, which are shown as interpretation; negative sentences,
which are sent back rather than checked; and Spanish and French word by word, which carry the
verified claims they cite.

The studio shows the results at `/match/nbr-riv/evidence/benchmark`.

## Speed

`python -m scripts.measure_speed` and `node --experimental-strip-types scripts/measure_browser_verifier.mjs`,
on one CPU of the build container (x86_64, Python 3.12, Node 22), no network:

| Measure | Result |
| --- | --- |
| Whole replay streamed with pacing removed: every event ingested and reduced, every cue and recap verified on the events received so far | 1,421 events and 23 verified cues and recaps in about 0.4 s, about 3,500 events a second |
| Verifying the cues and recaps that close at one moment (21 moments) | median about 1 ms, at most about 15 ms (the recap with the most claims) |
| All 79 claims the demo shows, on the server | about 56 ms |
| All 79 claims in the browser verifier (Node, the same module the page loads) | about 22 ms, after a 5 ms load of the compact log |

These are for scale, not a service-level promise: a phone is slower, and on Azure the
replay is paced to the chosen speed (1× to 60×). In the live checks of 23 October the first
stats card was verified on the server 312 ms of match time after its window closed, on the
first event to arrive after it.

## Live agent runs

From the [competition build record](competition-build-20261022.md): three evaluation runs of the
four specialists on Microsoft Foundry. 6 claims reached the verifier on first submission and
passed; 2 were sent back (one wrong number, one sentence saying more than its assertion); 3
malformed answers were stopped by the claim contract before verification; no unverified claim
reached an audience version; 128,908 tokens in total. A further run on Azure on 23 October
took 3 verification rounds ([live checks](azure-live-checks-20261023.md)).
